---
title: Read an edit or deletion log
description: Read before-and-after text, recoverable attachments and bulk deletion transcripts in the staff log channels.
---

Open the server’s edit log for a changed message or its deletion log for a removed one. Both can share a channel. The author named on a log wrote the original message.

## Edits and single deletions

**Message Edit** links to the surviving message and identifies its author and channel. Read the first block for the previous text and the second for the edited text. When Sylvan has both versions, it highlights the changes. *Unavailable* means Sylvan lacks that version. *Content truncated* means more text existed than would fit in the log.

**Message Delete** shows the author, channel and text Sylvan last saw. **Preceding message**, when present, takes you to the conversation immediately before the deletion. Sylvan also tries to download the attachments at deletion time. An omission count tells you how many files it could not include because of download failures or size limits.

## Bulk deletions

The summary gives the channel, the time of deletion and, when the audit log identifies them, the moderator who cleared the messages. Open `bulk-delete.txt` for the people who wrote them. Entries are ordered oldest first. Each line gives the **original posting time in UTC**, channel, author and text. A multiline message occupies several lines. A numeric user ID stands in for an unavailable username.

Bulk transcripts contain text only and can cover fewer messages than Discord deleted.

## What can be recovered

Sylvan keeps a copy of each eligible member message for **24 hours from its original posting time**. The deadline survives a restart and stays the same after an edit. Once the copy expires, Sylvan can no longer use it to publish a deletion log. Logs already posted in Discord stay in their log channel.

If a deletion has no log, check the message’s age and whether logging covered that channel when Sylvan observed the message and when it was deleted. Excluded channels, their threads and excluded categories can explain gaps. Log destinations and their threads are automatically excluded. An administrator can [check the destinations and exclusions](../../commands/logging/). Turning logging back on does not recover messages missed while it was off.
